# Architecture

## Naming and execution scope

StrokeWeaver Agent is the system. TACTIC is its internal evidence-applicability and conditional-repair controller. StrokeWeave is a historical alias, not another active service.

This package is generated-only. There is no patient-input path, clinical model loader, external URL execution or arbitrary command interface. A task preview cannot expand these capabilities.

## Modules

| Module | Responsibility |
| --- | --- |
| `run.py` / `cli.py` | Fixed CLI subcommands and generated report serialization. |
| `api.py` | Bounded task functions, scope declaration, package-source bindings and audit wrapper. |
| `controller.py` | Owned generated spatial workflow, dependency/evidence state, finite task models and shared policies. |
| `nifti_guard.py` | Strict binary NIfTI-1 generated recipe, geometry/unit/provenance guards and typed failure evidence. |
| `routing.py` | Deterministic supported-intent preview; no LLM or execution. |
| `audit.py` | In-memory JSON, escaped HTML, ZIP export and generated binary-slice PNG. |
| `tool_registry.json` | Disabled external DeepISLES contract and exposure metadata. |
| `streamlit_app.py` | Generated-only controls, actual result views and download buttons. |
| `legacy/source_index.json` | Curated historical source and adaptation provenance. |

The portable core depends on Python's standard library. Streamlit 1.55.0 supplies the optional interface and its normal dependencies. Torch, checkpoints, a clinical runtime and a private filesystem are not required.

## Generated spatial loop

```text
Registered generated fixture
  → input/context check
  → acquired technical observation
  → applicability/dependency validation
  → permitted bounded repair or retry
  → technical recheck
  → STOP with traceable arithmetic report, or REFER with unresolved reason
  → audit content hash and export
```

The fixtures cover a valid native grid, declared centimetre encoding, an axis-context conflict, non-binary input, unknown units and one transient analysis failure. This finite coverage is not a survey of naturally occurring clinical failures.

`observed` and `adopted` are separate states. A usable observation carries context and dependency identity; a context change can invalidate downstream evidence. Rejected data are not silently relabelled as valid evidence. STOP completes the **generated technical task**, not an independently correct stroke diagnosis. REFER is not proof of actual reviewer time saved.

## Shared planning controls

The declared finite models expose the same legal history, actions, tool outcomes, budget and root risk set to:

1. Dependency-aware deterministic workflow.
2. True rolling horizon-one policy, replanned after acquired observations.
3. Strong depth-two cascade.
4. Complete finite VOI.
5. TACTIC demonstration.

The last two deliberately use the same complete planner in this release. This preserves a strong reference rather than inventing a proprietary winning algorithm. The small task family has redundant mean/tail caps; it does not demonstrate a general separable risk constraint method.

Retain/mask/uninformative interventions are applied across all arms. The optional fixed-observation setting holds the initial acquired observation and its sunk cost fixed. These mechanism interventions are distinct from the main history-sharing comparison.

## Input and tool boundaries

The NIfTI guard accepts registered generated bytes only: small 3D little-endian float32 NIfTI-1, explicit scanner sform, millimetre spatial units, identity scaling and exact generated provenance. It rejects unsupported formats, nonfinite values, inconsistent geometry, missing modalities and altered byte provenance.

The advertised contracts are full DWI+ADC+FLAIR ensemble and a separately identified DWI+ADC SEALS component. Both external dispatch and patient admission remain disabled. No header replacement is treated as registration; matching grids do not establish biological alignment, brain coverage or lesion truth.

## Reference and report custody

Generated technical references are known construction/arithmetic values, not patient lesion annotations. A future scientific evaluation must be separated from online control: immutable candidates first, independent permitted reference scoring later. Protected labels and scores must never feed planning, memory, thresholds or repair selection.

The report wrapper records `scope`, package-source hashes, payload, UTC timestamp, scoped API wall time and `audit_sha256`. HTML escapes report text; ZIP export contains generated JSON and HTML. Verification recomputes a content digest: it is not a digital signature, trusted timestamp, immutable store or clinical certificate.

## Future integrations are separately gated

Adding a real tool requires task-specific rights, a versioned tool card, trained-on-data provenance, qualified runtime, applicable inputs, patient/exam semantics, protected-history exclusion and independent reference/endpoint/risk binding. The current app cannot accept a flag or upload that grants those authorities. Any future integration must retain shared strong controls, costs, failure receipts and negative outcomes.
